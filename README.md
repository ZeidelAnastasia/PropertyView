# PropertyView

## Описание проекта

**PropertyView** — REST API для управления информацией об отелях. Приложение предоставляет возможность получать сведения об отелях, создавать новые записи, выполнять поиск по различным параметрам, добавлять удобства и формировать статистические гистограммы.

Проект разработан на Java с использованием Spring Boot и Spring Data JPA. Для управления структурой базы данных применяется Liquibase, а для документирования API — OpenAPI и Swagger UI.

## Основные возможности

- Получение списка всех отелей с краткой информацией.
- Получение подробной информации об отеле по идентификатору.
- Создание нового отеля с указанием адреса, контактных данных и времени заезда.
- Добавление удобств к существующему отелю.
- Поиск отелей по названию, бренду, городу, стране и удобствам.
- Формирование гистограмм распределения отелей по бренду, городу, стране и удобствам.
- Валидация входных данных.
- Обработка ошибок с использованием стандартизированного формата `ProblemDetail`.

## Архитектура проекта

Приложение построено с использованием многослойной архитектуры.

Назначение основных компонентов:

- **API** — контракты REST API и OpenAPI-аннотации.
- **Controller** — обработка HTTP-запросов и передача данных сервисному слою.
- **DTO** — объекты для передачи входных и выходных данных.
- **Entity** — JPA-сущности, представляющие таблицы базы данных.
- **Service** — бизнес-логика приложения.
- **Repository** — доступ к данным и выполнение запросов.
- **Query** — построение динамических запросов с использованием JPA Criteria API.
- **Mapper** — преобразование DTO в сущности и обратно с помощью MapStruct.
- **Exception** — пользовательские исключения и централизованная обработка ошибок.

## Модель данных

В приложении используются следующие основные сущности:

- **Hotel** — информация об отеле: название, описание, бренд, адрес, контакты, время заезда и список удобств.
- **Address** — адрес отеля: номер дома, улица, город, страна и почтовый индекс.
- **Contacts** — контактная информация: телефон и электронная почта.
- **ArrivalTime** — время заезда и выезда.

Для связи отеля с адресом, контактами и временем заезда используются отношения `One-to-One`. Удобства хранятся в отдельной таблице `hotel_amenities` и связаны с отелем отношением `One-to-Many` на уровне таблиц.

Схема базы данных создаётся и обновляется с помощью Liquibase.

## REST API

Базовый адрес API:

```text
http://localhost:8092/property-view
```

### Отели

| HTTP-метод | Endpoint | Описание |
|---|---|---|
| GET | `/hotels` | Получение списка отелей |
| GET | `/hotels/{id}` | Получение отеля по ID |
| POST | `/hotels` | Создание нового отеля |
| POST | `/hotels/{id}/amenities` | Добавление удобств к отелю |

### Поиск отелей

**GET `/hotels/search`**

Поддерживаемые query-параметры:

| Параметр | Описание |
|---|---|
| `name` | Название отеля |
| `brand` | Бренд |
| `city` | Город |
| `country` | Страна |
| `amenities` | Список удобств |

Пример запроса:

```http
GET /property-view/hotels/search?city=Paris&brand=Hilton
```

При передаче нескольких удобств поиск выполняется по принципу AND: возвращаются отели, содержащие все указанные удобства.

### Гистограммы

**GET `/histogram/{param}`**

Поддерживаемые значения параметра `param`:

- `brand` — распределение отелей по брендам;
- `city` — распределение по городам;
- `country` — распределение по странам;
- `amenities` — распределение по удобствам.

Пример:

```http
GET /property-view/histogram/city
```

### Пример создания отеля

**POST `/hotels`**

Пример JSON-запроса:

```json
{
  "name": "Hilton Paris",
  "description": "Modern hotel in the city center",
  "brand": "Hilton",
  "address": {
    "houseNumber": 12,
    "street": "Rue de Rivoli",
    "city": "Paris",
    "country": "France",
    "postCode": "75001"
  },
  "contacts": {
    "phone": "+33123456789",
    "email": "paris@hotel.com"
  },
  "arrivalTime": {
    "checkIn": "14:00",
    "checkOut": "12:00"
  }
}
```

### Пример добавления удобств

**POST `/hotels/{id}/amenities`**

Пример JSON-запроса:

```json
[
  "Wi-Fi",
  "Swimming pool",
  "Parking",
  "Restaurant"
]
```

Повторное добавление уже существующего удобства не создаёт дубликат.

## Документация API

Для просмотра интерактивной документации используется Swagger UI.

После запуска приложения откройте:

```text
http://localhost:8092/property-view/swagger-ui.html
```

Документация OpenAPI доступна по адресу:

```text
http://localhost:8092/property-view/api-docs
```

Swagger UI позволяет просматривать доступные endpoints, изучать параметры запросов, модели данных и выполнять HTTP-запросы непосредственно из браузера.

## Обработка ошибок

Для централизованной обработки исключений используется `@RestControllerAdvice`.

API возвращает ошибки в формате `ProblemDetail`.

Основные HTTP-статусы:

| Код | Описание |
|---|---|
| 200 | Запрос выполнен успешно |
| 201 | Ресурс успешно создан |
| 400 | Некорректные входные данные |
| 404 | Запрашиваемый отель не найден |
| 409 | Конфликт данных |
| 500 | Внутренняя ошибка сервера |

## Тестирование

Для проверки корректности работы приложения используются:

- модульные тесты сервисного слоя с JUnit 5 и Mockito;
- тесты репозиториев с использованием `@DataJpaTest`;
- тесты REST-контроллеров с использованием `@WebMvcTest` и MockMvc.

Тесты проверяют бизнес-логику, работу с базой данных, поиск и фильтрацию отелей, формирование гистограмм, валидацию запросов и обработку исключений.
